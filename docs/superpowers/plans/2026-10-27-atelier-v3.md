# Étape 2 — sauvegarde v3 et atelier à six postes : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** la camionnette s'améliore à l'atelier : six postes en cinq niveaux Mk I à V, achetés avec des composants ◆ (et des pièces de secteur pour Mk III à V), toujours actifs hors emplacement, visibles au garage. La sauvegarde passe en `ssx_meta_v3`, avec remboursement des anciens nœuds repris par l'atelier.

**Architecture :** les règles pures (tableau des postes, coûts, effets, achat) vivent dans un nouveau `src/data/atelier.js`, testé sous Node avec le chargeur `vm` de `tools/composants_test.js`. `src/data/meta.js` porte le modèle v3 et la migration. Les stats de départ passent par une seule fonction `applyGlobalGear(stats, meta)` (atelier puis arbre restant) utilisée par la mission, le tuto et l'aperçu. L'arbre actuel **reste jouable** pour tout ce que l'atelier ne reprend pas (lasers, missiles, drones, etc.) jusqu'à l'étape 3, qui le remplace par la R&D. Le garage (`src/home/garage.js`) remplace le sélecteur d'aperçu par la liste des postes.

**Tech Stack :** Phaser 3.70 en scripts classiques (`mixin(GameScene, {…})`), tests Node (`tools/*_test.js`) et Playwright Python (`tools/home_test.py`, `perks_test.py`, `level_test.py`).

**Spec :** `docs/superpowers/specs/2026-10-27-progression-design.md` (§4 atelier, §9 sauvegarde et migration, §11 textes). Plan de l'étape 1 : `docs/superpowers/plans/2026-10-27-progression-agp.md`. Garage : `docs/REPRISE-GARAGE.md`.

## Décisions de ce plan (à relire par Guet)

1. **Migration en deux temps.** Le spec (§9) rembourse tout l'ancien arbre d'un coup, mais la R&D n'existe qu'à l'étape 3 : tout rembourser maintenant ferait perdre lasers, missiles et drones achetés. Étape 2 : on rembourse **seulement les 28 nœuds repris par l'atelier** ; le reste de l'arbre est conservé tel quel (`meta.tree`). L'étape 3 fera le remboursement du reste.
2. **Pièces de secteur.** Elles n'apparaissent qu'à l'étape 4. Mk III à V sont donc affichés **verrouillés** (« PIECES DE SECTEUR REQUISES ») et non achetables en jeu normal ; un bouton DEV (`?dev`) accorde des pièces pour tester.
3. **Valeurs des Mk et prix** : provisoires (tableaux ci-dessous), à régler avec `sim_balance.py` (tâche 6). Un seul barème de prix pour les six postes.
4. **Tutoriel.** Le spec (§16) dit que le tuto ignore atelier et R&D, mais le code et `CLAUDE.md` appliquent les atouts globaux au tuto. On **garde le comportement actuel** (l'atelier s'applique aussi au tuto) ; personne n'a d'achat avant le tuto, donc aucun effet réel.
5. **Ascension supprimée** (code mort, spec §9) : `meta.asc` et `applyAscension` disparaissent.
6. **Champ `meta.fragments` renommé `meta.composants`** (spec §9), pour que le code dise la même chose que le jeu.
